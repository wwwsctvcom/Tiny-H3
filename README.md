# Tiny-H3

**A complete, minimal MiniMax-H3 project: one model config, one real-world training corpus, and a
text → video + audio pipeline that trains on a single RTX 5090.**

MiniMax-H3 packs text, video and audio into one sequence and denoises them together with an
omni-modal diffusion transformer. Tiny-H3 reproduces every stage of that pipeline with the
officially released MiniMax-H3 video/audio VAEs, the same scheduler, the same packed-sequence
layout and flow convention — from raw clips to a playable MP4. The shipped DiT is **1.23B
parameters** (the official one is 24.4B), which fits a 32 GB card with room to spare.

| | Official MiniMax-H3 | Tiny-H3 |
|---|---|---|
| DiT | 24.4B (hidden 5376 × 50 layers) | **1.23B** (hidden 1408 × 20 layers, `configs/stage4_xlarge.json`) |
| Text encoder | Qwen3-VL-8B (66 GB) | frozen **Qwen3-0.6B**, 128-token prompts |
| Video / audio VAE | official | **official, frozen** |
| Latent space / packed sequence / scheduler / flow sign | — | **identical to the official model** |

---

## Training data and results

Training corpus: **5,495 real-style segments** sliced from
[DiffSynth-Studio/MiniMax-H3-Self-Generated-Dataset](https://modelscope.cn/datasets/DiffSynth-Studio/MiniMax-H3-Self-Generated-Dataset)
(1,100 clips generated by the official 24.4B MiniMax-H3, 124 frames each, cut into 22-frame
segments on the 17n+5 grid with synced audio — `tools/segment_clips.py`).

Training: 9,000 steps (~39 epoch), batch 8×3, lr 2e-4 cosine, one RTX 5090 at 99% utilization,
2.8 hours, peak VRAM 11.6 GB:

![loss curve](assets/loss_curve.png)

### Results — 7-clip deep-overfit: generations match the training data

The headline result. A 4,000-step deep-overfit fine-tune of the 1.23B checkpoint on **seven
showcase segments** (≈4,570 epoch on those clips) drops reconstruction error to
**5.5–9.3 / 255 across all seven** — and the phase drift disappears with it (direct vs
best-shift MAE are equal: the regenerated motion follows the source trajectory). Side by side,
the generations are near-indistinguishable from the training clips:

Command (resume from the shipped checkpoint with `--init`; the memory set is a plain latent
cache over the chosen segments):

```bash
python -m tiny_h3.train.train_full --latents data/mem8_latents \
  --preset configs/stage4_xlarge.json --init runs/stage4_1232m/final \
  --out runs/mem8_overfit --steps 4000 --batch-size 8 --lr 6e-5
python tools/inference.py --checkpoint runs/mem8_overfit/final \
  --prompt <segment prompt> --size 384 --steps 48
```

### Full-corpus reconstruction (all 5,431 segments)

The same checkpoint trained on the whole corpus (11,500 + 500 steps) reaches a mean
reconstruction error of ~38/255 across random segments: capacity, not training time, is the
binding constraint at this scale. Fidelity per clip is tunable by choosing how many clips share
the model — 7 clips give ~7/255, 5,431 clips ~38/255.

Prompt used for all three: the dataset's structured H3 prompts (*integrated_multimodal_description:
[Shot 1] Live-action, cinematic ...*), truncated to 128 tokens.

**Why generated clips are hard to "read" frame by frame.** Diffusion sampling regenerates the
0.92-second motion trajectory freely: the action in a reconstruction drifts a few frames relative
to the source clip, so a naive side-by-side or per-frame comparison looks wrong even when the
content is right. Phase-aligned comparison (match each generated frame to the nearest of the
source's ±3 frames) shows near-parity. Two more factors cap fidelity today: prompts are truncated
to 128 of 500+ tokens, and each segment is only 0.92 s long.

## Quick start

Prerequisites: one NVIDIA GPU (24 GB+ recommended), Python 3.10+, ~40 GB disk. No ffmpeg install
needed (bundled).

### 1. Clone

```bash
git clone https://github.com/wwwsctvcom/Tiny-H3.git tiny-h3 && cd tiny-h3
```

### 2. Environment (China mirrors)

```bash
export PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple   # skip on AutoDL (bundled mirror)
export HF_ENDPOINT=https://hf-mirror.com                        # set by default in scripts/env.sh
bash scripts/setup_env.sh
```

### 3. Download model components (~12 GB via hf-mirror)

```bash
source scripts/env.sh
bash scripts/download_assets.sh
```

| Component | Size | Purpose |
|---|---|---|
| H3 video VAE + audio VAE | 11 GB | encode training data, decode generated clips |
| Qwen/Qwen3-0.6B | 1.2 GB | frozen text encoder |

### 4. Build the training corpus

Download the source dataset from ModelScope and slice it into training segments:

```bash
python tools/segment_clips.py \
    --metadata <dataset>/metadata.jsonl --video-root <dataset>/videos \
    --out data/h3selfgen_seg384 --segment-frames 22 --size 384 --workers 24
python tools/prepare_latents.py --data-dir data/h3selfgen_seg384 \
    --out data/h3selfgen_seg384/latents --device cuda --size 384 --text-tokens 128 \
    --batch-size 2 --split train
```

### 5. Train

```bash
python -m tiny_h3.train.train_full \
  --latents data/h3selfgen_seg384/latents \
  --preset configs/stage4_xlarge.json \
  --out runs/stage4_1232m --steps 9000 --batch-size 8 --grad-accum 3 --lr 2e-4
```

~1.1 s/step on a 5090 (9,000 steps ≈ 2.8 h at 99% GPU utilization, 11.6 GB). Loss prints live
and lands in `runs/stage4_1232m/metrics.jsonl`; checkpoints every 3,000 steps. Useful training
options: `--init <checkpoint>` resumes from a trained model; `--eval-every N --patience M` adds
early stopping on a held-out split.

### 6. Inference

```bash
python tools/inference.py --checkpoint runs/stage4_1232m/final \
  --prompt "integrated_multimodal_description: [Shot 1] Live-action, cinematic, wide shot. ..." \
  --out outputs/inference --steps 48 --size 384
```

Every pipeline stage is printed in order (DiT load → packed layout → text encoding → denoising →
official VAE decode → MP4 mux). Repeat `--prompt` for multiple clips. For the trained corpus'
own prompts, sample several seeds and keep the clip you like — sampling is a draw from the
model's distribution, not a deterministic lookup.

## Scaling record

Measured across this repo's history with the same protocol (the task got harder down the table —
more data, higher resolution, longer prompts):

| Model | Data | Val loss |
|---|---|---|
| 63.7M | 512 procedural clips @ 256p | 0.641 |
| 190M | 4,096 procedural clips @ 256p | 0.256 |
| 386M | 9,591 mixed clips @ 256p | 0.262 |
| 756M | 5,431 real-style segments @ 384p, 128 tokens | 0.806 |
| **1.23B** | **5,431 real-style segments @ 384p, 128 tokens** | **0.438** |

Reconstruction fidelity on training clips scales with parameters: the 1.23B checkpoint rebuilds
them near-indistinguishably at 384×384, where 386M could only convey palette and mood.

## Improvement roadmap

Ordered by expected impact on making generations clearer and easier to read:

1. **Longer segments (39–56 frames).** 0.92 s carries almost no narrative; 2.3 s segments give
   viewers something to follow. Latent sequence grows ~2.8× — the main memory cost.
2. **Full-length prompts.** Truncating 500-token structured prompts to 128 loses scene detail.
   Raise `--text-tokens` to 256+ (packed sequence grows linearly).
3. **More source data.** 7,461 of the dataset's 8,560 T2VA clips are not downloaded yet; every
   doubling of unique scenes directly improves reconstruction coverage.
4. **Bigger DiT.** `configs/stage4_xlarge.json` scales up (hidden 1536–1792, 22–24 layers ≈
   1.6–2 B) — still single-5090 territory with batch 6–8, at linearly growing training time.
5. **Deterministic visualization protocol.** To judge fidelity, sample several seeds at fixed
   48+ steps and compare with ±frame alignment against the source clip, not naive per-frame
   diffs.
6. **Multi-GPU.** `torchrun --nproc_per_node=N ... train_fsdp` shards the same config across
   cards; the 1.23B model trains unchanged.
